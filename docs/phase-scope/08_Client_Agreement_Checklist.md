# Лист согласования Фазы I с клиентом — шаблон

Этот файл будет заполнен после внутренних ответов. Клиенту следует направлять не все внутренние сомнения, а компактный набор решений.

## 1. Утверждаем цель Фазы I

- [ ] Согласован end-to-end результат Фазы I.
- [ ] Согласован перечень запускаемых подразделений.
- [ ] Согласована дата готовности и период опытной эксплуатации.

## 2. Утверждаем функциональный состав

Для каждого модуля должна появиться таблица:

| Функция | Входит | Не входит | Зависимость клиента | Критерий приёмки |
|---|---:|---:|---|---|
|  |  |  |  |  |

## 3. Утверждаем исключения

- [ ] Аптека и склады.
- [ ] Полный операционный блок.
- [ ] Расширенная сестринская работа.
- [ ] Качество и безопасность.
- [ ] HR и зарплата.
- [ ] Полный страховой и договорный контур.
- [ ] Portal, Mobile и Telemedicine.
- [ ] BI, Research и AI.
- [ ] Не перечисленные внешние интеграции.

## 4. Утверждаем интеграции Фазы I

Для каждой включённой интеграции нужен отдельный паспорт и критерий приёмки.

| Интеграция | Входит в I | Система/версия | Ответственный клиент | Ответственный поставщик | Third-party cost |
|---|---:|---|---|---|---|
|  |  |  |  |  |  |

## 5. Утверждаем формы, справочники и отчёты

- [ ] Перечень медицинских форм.
- [ ] Перечень специальностей.
- [ ] Классификаторы.
- [ ] Каталог услуг и прейскурант.
- [ ] Роли и матрица доступа.
- [ ] Перечень отчётов и формулы показателей.

## 6. Утверждаем данные

- [ ] Источники миграции.
- [ ] Состав и исторический период.
- [ ] Формат передачи.
- [ ] Ответственность за очистку.
- [ ] Дата финальной выгрузки и cutover.

## 7. Утверждаем нефункциональные требования

- [ ] Развёртывание.
- [ ] Пользователи и нагрузка.
- [ ] Производительность.
- [ ] Доступность.
- [ ] RPO/RTO.
- [ ] Безопасность и хранение данных.
- [ ] Поддержка и SLA.

## 8. Утверждаем управление изменениями

- [ ] Всё, что не включено в подписанную матрицу, оценивается отдельно.
- [ ] Изменение scope может изменить срок и стоимость.
- [ ] Задержка данных, доступов или решений клиента сдвигает зависимые сроки.
- [ ] Архитектурная готовность к будущему модулю не означает реализацию этого модуля в Фазе I.
