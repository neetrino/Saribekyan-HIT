# Փուլ I-ի մեկնարկից հետո Պատվիրատուից պահանջվող նյութերը

> **Authority: NON_AUTHORIZING. Lifecycle: HISTORICAL client message.** `OPERATIONAL_TEMPLATE` canonical lifecycle չէ։ Սա պատվիրատուին ուղղված նամակի նախագիծ է, ոչ import schema, ոչ client-approval evidence և ոչ coding authorization։ Թվարկված ICD-ն, դեղերը, չափման միավորները, հղումային միջակայքները և կրիտիկական շեմերը լրացնում է Պատվիրատուն։ Չստացված արժեքը ագենտը չի հորինում և դրանով աղյուսակ կամ կանոն չի ստեղծում։

Հարգելի գործընկերներ,

Պայմանագրի և Փուլ I-ի տեխնիկական առաջադրանքի ստորագրումից հետո Պատվիրատուից պահանջվում են ստորև նշված երկու **բովանդակային** փաթեթները։ Դրանք միակ post-signing prerequisites-ը չեն և չեն փակում task-level business/security/technical blockers-ը։ Յուրաքանչյուր implementation task շարունակում է պահանջել gate-ի համապատասխան որոշումներն ու `GO` record-ը։ Փաթեթները բժշկական համալիրի փաստացի տվյալներն ու բովանդակությունն են, ոչ լրացուցիչ գործառույթներ։

1. **Կազմակերպական և սկզբնական տվյալների փաթեթ։** Անհրաժեշտ կլինի տրամադրել առաջին գործարկման ստորաբաժանումների, ծառայությունների, մասնագիտությունների, հիվանդասենյակների, մահճակալների, աշխատակիցների, պաշտոնների, դերերի համապատասխանեցման, ժամանակացույցերի, ծառայությունների կատալոգի, կոդերի, գների, վճարողների, կիրառվող ICD-ի, դեղերի և լաբորատոր հետազոտությունների տեղեկատուների, չափման միավորների, հղումային միջակայքների ու կրիտիկական շեմերի պատրաստ և հաստատված տվյալները։ Փոխանակման format/template-ը նախապես չի ենթադրվում. այն առանձին համաձայնեցվում է՝ հաստատված import capability-ի և data mapping-ի հիման վրա։ Միայն դրանից հետո կատարվում են համաձայնեցված սկզբնական կարգավորումն ու ներբեռնումը։

2. **Փաստաթղթերի և բժշկական ձևանմուշների փաթեթ։** Անհրաժեշտ կլինի տրամադրել առաջին գործարկման համար անհրաժեշտ բժշկական և վարչական փաստաթղթերի փակ ցանկը, Ձեր մոտ առկա նմուշները, պետական կամ ներքին չափորոշիչները և բովանդակությունը հաստատող պատասխանատու մասնագետներին։ Միայն այդ փակ ցանկի ու աղբյուրների հիման վրա կարող են reference օրինակներ առաջարկվել։ Ոչ մի հրապարակային օրինակ, բժշկական դաշտ, պարտադիրություն, default կամ validation չի ներմուծվում առանց Ձեր լիազորված բժշկական կամ իրավաբանական մասնագետի գրավոր հաստատման։ Տեխնիկական կարգավորումը կատարվում է միայն հաստատված բովանդակությամբ և ընտրված form capability-ի սահմաններում։

Այս երկու փաթեթների պատրաստումը կարող է սկսվել պայմանագրի ստորագրումից հետո, սակայն դրանց առկայությունը ինքնուրույն business implementation authorization չէ և չի փոխարինում չփակված blocker-ներին։
