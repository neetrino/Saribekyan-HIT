## Что именно требует источник

Источник содержит четыре перечня и в каждом использует формулировку **«как минимум»**. Всего перечислены 52 строки требований, но это не обязательно 52 отдельных экрана: некоторые показатели повторяются между модульным и руководительским отчётом.

Источник требует готовые отчёты/показатели и экспорт, но **не требует в I универсальный пользовательский конструктор отчётов**. Полный BI и стратегическая аналитика прямо исключены из I — строки 2906–2928.

## Повторения, которые можно реализовать одним результатом

В разных разделах повторяются:

- выполненные исследования/услуги;
- невыполненные заказы;
- распределение услуг по типу;
- среднее время готовности результата;
- выручка по подразделению;
- выручка по услуге;
- скидки;
- возвраты.

Поэтому корректнее согласовать не число экранов, а закрытый реестр **уникальных результатов**, где один отчёт может покрывать несколько строк источника.

## Неопределённые параметры

Источник не задаёт:

- точные формулы;
- состав колонок;
- группировки и детализацию;
- правила округления;
- контрольные примеры;
- допустимое время расчёта;
- разграничение между отдельным отчётом, dashboard widget и фильтрованным представлением;
- верхнюю границу после слов «как минимум».

## Предлагаемая минимальная граница I для подтверждения

1. I покрывает каждый явно перечисленный информационный результат, но повторяющиеся требования могут быть объединены.
2. До разработки стороны утверждают приложение: `название / показатели / формула / фильтры / представление / экспорт / роль`.
3. Универсальный report builder, полный BI, прогнозы и дополнительные неуказанные отчёты не входят в I.
4. Новый отчёт сверх утверждённого реестра не считается автоматической детализацией существующего отчёта.

Эта граница следует из перечисленного минимума и прямого исключения полного BI, но должна быть подтверждена клиентом из-за слов «как минимум».
